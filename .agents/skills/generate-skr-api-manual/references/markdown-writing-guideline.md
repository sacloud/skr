# Markdown チュートリアル作成ガイドライン

生成先は `docs/tutorials/<service>-api.md` です。IaaS API のように複数のリソースを扱う場合は
`docs/tutorials/<service>-api/<resource>.md` に分けます。リポジトリでは Markdown で記述し、
特定の静的サイトジェネレーター専用の構文には依存しません。

## 構成と可読性

- `#` はページタイトル、`##` は大項目、`###` は手順内の小項目に使います。
- 先頭にサービスの用途を短く説明し、注意事項があれば本文より前に置きます。
- 手順は番号付きリストまたは `## Step 1: ...` の見出しで明確にします。
- 長い段落を避け、用語は初出時に説明します。コマンドの前に目的と必要な値を説明します。
- コマンド、JSON、出力例は適切な言語ラベル付き fenced code block に入れます。
- `list`、`find` などの一覧・検索結果を作成後やクリーンアップ後の確認に使う場合は、コマンドの直後に確認できた出力例も掲載します。空結果、他リソースを含む全件一覧、端末幅による省略など、実際の結果の意味が分かる形で示します。
- 読者がコマンドをコピーできるようにし、置換が必要な値には
  `PROCESS-CONFIGURATION-ID` や `EVENT-SOURCE` のような明示的な placeholder を使います。
- 複雑な JSON はファイル例として示し、コマンドの引用符エスケープに依存させません。
- コマンド例と flag は現在の `skr ... --help` と照合します。非対応の flag、alias、
  出力形式を記載しません。
- リンク文字列はリンク先が分かる説明にし、裸の URL を並べません。

## 注意事項

課金、データ変更、外部通知、イベント発火などの注意は、対象の公式資料に基づいて
具体的に記述します。根拠のない一般的な警告を追加しません。

GitHub などでも読めるよう、注意事項は通常の Markdown として表現します。

```markdown
> [!WARNING]
> この手順は承認されたプロファイルにリソースを作成します。
> 実行前に `skr config current` と対象環境を確認してください。
```

実際にライブ環境を操作するチュートリアルの場合は、作成・変更・削除するもの、
影響、クリーンアップを具体的に書きます。secret をコマンド例、ログ、出力例に含めません。

## コードブロック

shell コマンド:

````markdown
```console
$ skr eventbus-api process-configuration list
```
````

JSON ファイル:

````markdown
```json
{
  "CommonServiceItem": {
    "Name": "example-job",
    "Settings": {
      "Destination": "simplemq",
      "Parameters": "{\"queue_name\":\"QUEUE-NAME\",\"content\":\"hello\"}"
    }
  }
}
```
````

出力を掲載する場合は、実環境の ID、名前、説明、時刻、トークン、アカウント情報を
マスクまたはプレースホルダーに置換し、出力例が編集済みであることを明記します。
全件一覧の一部を抜粋した場合や、端末幅により列・値が省略される場合はその旨を記載します。
空の結果による削除確認も、確認した `No results` や `[]` などを掲載します。
実際には確認していない成功結果を捏造しません。

## 事実と参照元

- サービスの説明、制約、依存関係、動作結果に関する主張は公式マニュアルまたは対象 SDK
  バージョン内の説明にリンクします。
- 確認できた仕様は CLI 自身の説明として直接記述します。「公式マニュアルによると」など、
  第三者の説明として距離を置く表現は使わず、根拠を参照リンクで示します。情報源の記録は
  執筆時の事実確認に使い、利用者向けの本文には調査過程を持ち込みません。
- command syntax、JSON request 型、SDK の option/null 動作はこのリポジトリの実装と
  `--help` に合わせます。SDK/API の入力フィールドをサービス仕様として過剰に解釈しません。
- ユーザー環境に依存する値と、公式仕様で決まっている値を区別します。
- ページ末尾に関連する公式マニュアルと SDK ドキュメントの参照をまとめます。

## リンクの検査

Markdown の `[label](https://...)` と `<https://...>` の外部リンクを検査します。
ローカル画像・相対リンクは存在確認も行い、見出しリンクや `mailto:` は HTTP リクエスト
対象にしません。リンク変更後は以下を実行します。

```sh
python3 ./.agents/skills/generate-skr-api-manual/scripts/check_tutorial_links.py
```
