# ADR 0078: skr 全体で統一した text → JSON 簡易表記を共有パーサーで扱う

- Status: Accepted
- Date: 2026-11-11

## 背景

JSON や配列で表現される API パラメータを、高レベルコマンドで JSON を書かずに指定したい場面は、EventBus 以外のサービスでも起こります。[ADR 0041](0041-server-repeatable-disk-and-nic-options.md) は Server Create の `--disk` と `--nic` に、[ADR 0076](0076-eventbus-trigger-condition-option.md) は EventBus トリガーの `--condition` に、それぞれカンマ区切りの `key=value` リスト構文を導入しました。2つの構文は、反復可能オプションの 1 回の指定を配列の 1 要素に対応させる点、要素の分解と値の扱い、エラーの原則などがほぼ同じです。一方で、規則が ADR とドメインごとの実装に分かれていました。このままだと、次のサービスが同種の入力を必要としたときに、構文の方言が乱生します。

PR #227 のレビューで、この構文を eventbus 固有にせず、skr として統一された text → JSON の簡易表記として定義することが求められました。

## 決定

カンマ区切りの `key=value` リストを、skr 全体で統一した text → JSON 簡易表記として定義します。解析と検証は共有パッケージ `internal/textjson` が担い、既存の `--disk`、`--nic`、`--condition` はこのパーサーへ統一します。新しいオプションも、独自の構文解析を追加せずこのパーサーを使います。

- 1 回の指定を 1 つの構造 (配列の 1 要素など) に対応させ、複数の構造は反復可能オプションで組み立てます。指定順序を保持します。
- 指定はカンマ区切りの要素に分解します。各要素は最初の `=` でキーと値に分け、後続の `=` は値の一部として保持します。
- `=` を含まない要素、空の要素、キーまたは値が空の要素はエラーにします。
- 値は字義どおり扱い、前後の空白の除去や引用符・エスケープの解釈は行いません。カンマは要素の区切り専用で、値にカンマを含めることはできません。表現できない入力は JSON 経路を使います。
- キーの集合はオプションごとのスキーマで定義します。スキーマはキー名と、必須かどうか、同一指定内での反復を許可するかどうかを表します。未対応のキー、必須キーの欠落、反復を許可しないキーの重複はエラーにします。反復を許可するキーは出現順に値のリストを組み立てます。
- エラーメッセージには入力の値を含めません。入力に秘密情報が含まれていても表示しません ([ADR 0041](0041-server-repeatable-disk-and-nic-options.md) と同じ)。
- 値はすべて文字列として受け取ります。整数や列挙値への変換、API のパターンとの整合の検証は、マッピングする側 (CLI の変換処理と service 層) が行います ([ADR 0047](0047-minimize-cli-request-body-validation.md))。
- この表記を新しいオプションに適用するときは、その操作の ADR で対象とキーのスキーマ、API リクエスト構造への変換を定義し、既存の JSON 入力経路を維持します。`--request` との相互排他、未指定値、構文エラー、変換をテストします。

`--disk` と `--nic` では、値に `=` を含める指定の扱いが変わります。共通パーサーは最初の `=` で要素を分割するため、`=` を含む値は構文エラーではなく、キーごとの値の検証 (正の整数、列挙値) でエラーになります。受け付ける入力の範囲は変わりません。

## 影響

- 共有パッケージ `internal/textjson` を追加し、2つのドメインの構文解析を統一します。各オプションはキーのスキーマと、解析結果を API リクエスト構造への変換だけを定義します。
- [ADR 0041](0041-server-repeatable-disk-and-nic-options.md) と [ADR 0076](0076-eventbus-trigger-condition-option.md) の構文規則のうち、表記として共通な部分を本 ADR に委ねます。
- 今後、他のサービスで同種の入力を導入するときは、独自の方言を追加せず本 ADR と共有パーサーを使います。

## 検討した選択肢

- 構文をドメインごとのままにする方式: 次のサービスが同種の入力を導入するたびに規則が分岐し、利用者が構文を学び直すことになります。採用しません。
- 型付きの値や入れ子を表現できる拡張構文を定義する方式: 簡易表記の対象は「JSON を書かずに済む単純な構造」であり、複雑な構造は JSON 経路に残します ([ADR 0007](0007-api-request-input.md))。今回の適用例でも必要がないため採用しません。
- コマンド生成器に組み込み、生成コマンドへ自動適用する方式: 適用対象は操作ごとの設計判断であり、配列への自動適用は禁止しています ([ADR 0041](0041-server-repeatable-disk-and-nic-options.md))。採用しません。
