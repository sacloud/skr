# ADR 0032: IAM API コマンドを拡張する

- Status: Accepted
- Date: 2026-10-08

## Context

[ADR 0031](0031-iam-api-commands.md) では IAM ユーザー、グループ、ポリシーバインディングを段階的に公開しました。`sacloud-sdk-go v0.3.0` は、それらに加えて認証条件、フォルダ、ロール、ID ポリシー、組織、プロジェクト、API キー、SCIM、サービス利用ポリシー、サービスプリンシパル、SSO、2 要素認証の API を公開しています。

IAM の利用者がこれらの操作も CLI から実行できるようにしつつ、認証や権限へ影響する操作と秘密情報の入出力を明確に扱う必要があります。

## Decision

- `skr iam-api` に SDK の残り 13 API 群を追加します。
- 対象には `auth`、`folder`、`iam-role`、`id-policy`、`id-role`、`organization`、`project` を含めます。
- `project-api-key`、`scim`、`service-policy`、`service-principal`、`sso`、`user-2fa` も追加します。
- SDK の公開操作とリクエスト型を確認し、各 API 群の操作範囲、CLI 引数、説明を `api/commands/iam-*.json` に明示して `cmd/apigen-api` から生成します。CLI 登録、Runtime、SDK factory は `internal/cli` と `internal/iamapi` で接続します。
- サービスプリンシパルの公開鍵とアサーションは通常の引数やインライン JSON に含めず、ファイルまたは標準入力から読み込む手書きコマンドにします。シークレットを含む API 応答を使う場合は、利用者が出力を安全に保存できるヘルプとチュートリアルを用意します。
- `folder move` と `project move` は対象 ID のリストと移動先フォルダを必須指定にし、SDK の移動操作を利用します。
- IAM のライブ E2E は、選択中プロファイルの表示後にランダムな識別子でユーザー、グループ、フォルダ、プロジェクト、サービスプリンシパルを作成し、読み取り・更新・所属・メールアドレス操作を確認して、依存関係の逆順で削除します。名前の衝突やリソース識別の不一致を検出した場合は既存リソースを変更せず停止します。
- 認証条件、ポリシー、SSO、SCIM、サービス利用設定、2 要素認証、API キーや公開鍵の変更は、ログイン・権限・連携・秘密情報に影響するため、このライブ E2E の対象にしません。これらの操作は SDK モックを使った CLI テストとヘルプで検証します。

## Consequences

- IAM SDK の追加 API 群を `skr iam-api` から利用でき、通常の CRUD 操作だけでなくフォルダとプロジェクトの移動も実行できます。
- API の追加やヘルプ変更は JSON 設定を編集して再生成します。生成コードを直接編集しません。
- ライブ E2E は選択した組織にテスト用 IAM リソースを作成し、一時的にメールアドレスとグループ所属を変更します。実行には専用の確認フラグが必要で、証跡は非公開のローカル領域に保存します。
- すべての追加 API 操作をライブ環境で実行するわけではありません。ログイン情報や権限、秘密情報に影響する操作は、利用者が別途明示的に確認しない限り、ライブ E2E の対象外です。

## Alternatives considered

- IAM の全 API を1つの汎用 JSON コマンドとして公開する方法: 各操作の名前付きコマンド、入力制約、秘密情報の扱いをヘルプで説明しにくいため採用しません。
- 認証や権限に影響する更新もライブ E2E で実行する方法: 既存利用者のログインやアクセス権、外部連携を意図せず変更する可能性があるため採用しません。
- サービスプリンシパルの鍵やアサーションをコマンド引数で受け付ける方法: プロセス一覧やシェル履歴に入力内容が残り得るため採用しません。
