# ADR 0028: サービスプリンシパルキーを標準の認証設定フローにする

- Status: Accepted
- Date: 2026-10-07

## Context

`skr` にはプロファイルの一覧・選択・表示コマンドがありますが、認証情報を設定するフローはありません。認証情報も profile の一部として扱い、profile の作成・編集時にまとめて設定できるようにします。

認証情報には API キーとサービスプリンシパルキーがあります。今後の標準的な利用方法はサービスプリンシパルキーとし、利用者はコントロールパネルで用意したキーを profile に設定します。

profile v1 は `credentials` に API キーとサービスプリンシパルキーの項目を定義し、両方が設定された場合はサービスプリンシパルキーを優先します。SimpleMQ のキュー単位 API キーは、さくらのクラウド自体の認証情報とは用途が異なります。

## Decision

- 認証情報を設定する対話フローでは、サービスプリンシパルキーを標準の認証方式として案内します。
- `skr` に API キーを入力・保存するための設定フローは設けません。
- 既存の API キーを使う利用者は、sacloud-sdk-go がサポートする形式で profile ファイルを手動編集します。
- この決定は CLI の設定フローに関するものです。既存の profile や sacloud-sdk-go が持つ API キー認証の動作を削除・禁止するものではありません。
- SimpleMQ のキュー単位 API キーは認証設定フローや共通 profile では管理せず、SimpleMQ のメッセージ操作に個別に渡します。
- 認証情報は profile の設定項目として扱い、profile の作成・編集フローで設定します。認証専用の `auth login` / `auth setup` コマンドは追加しません。profile の切り替えは作成・編集とは別の操作にします。
- 出力形式や既定ゾーンなどの CLI 設定は認証情報の登録フローに含めません。

## Consequences

- 新しい利用者向け手順では、コントロールパネルで用意したサービスプリンシパル ID、キー ID、秘密鍵を profile に設定する方法を説明します。
- API キー方式を使う利用者には profile ファイルを手動編集する手順が必要です。CLI の認証設定フローを使う利用者には、サービスプリンシパルキーを案内します。
- profile v1 および sacloud-sdk-go の対応状況を確認してから、保存形式と秘密鍵の入力方法を実装します。秘密情報はコマンドライン引数や通常の設定表示に露出させません。
- API キー認証を CLI の設定フローに追加する必要が生じた場合は、この決定を再検討します。

## Alternatives considered

- API キーとサービスプリンシパルキーの両方を対話フローで選択可能にする方法: API キーを標準の設定経路に残すため、サービスプリンシパルキーを基本とする方針に合わず採用しません。
- profile の JSON/YAML を利用者が直接編集する方法を標準にする: 認証情報の入力にファイル形式を意識させるため、標準の利用者向けフローにはしません。
