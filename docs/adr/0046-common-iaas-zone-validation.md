# ADR 0046: IaaS のゾーン検証を生成コードの共通仕様にする

- Status: Accepted
- Date: 2026-10-15

## Context

IaaS の各操作は単一ゾーンを対象としますが、空文字列と `all` の拒否を各リソースの `request_validator` に重複して実装していました。Zone と ID をまとめた検証関数では、ゾーンの共通仕様とリソース固有の検証の責務が混在しています。

## Decision

- 操作の生成設定に `validate_zone: true` を指定すると、リクエスト構築後、`request_validator` と API クライアント生成の前に `zones.ValidateSingleZone(request.Zone)` を呼び出します。
- フラグ経路と JSON 経路の両方で同じ検証を適用します。`--zone` の存在だけから検証を推測せず、設定で明示します。リクエストの `Zone` は文字列である必要があり、型の不一致は生成コードのビルドで検出します。
- `zones.ValidateSingleZone` は空文字列と `all` を拒否します。空文字列のエラーは `Zone が必要です (--request JSON も指定できます)` に統一します。それ以外のゾーン名の存在確認は追加しません。
- リソース固有の `request_validator` からゾーン検証を削除し、ID や入力項目の制約を検証します。ゾーン検証しか行わない関数は削除します。
- `validate_zone` はリクエストを持つ生成操作に限定します。手書きの Server Boot はハンドラーから共通関数を直接呼び出し、固有の validator へゾーン検証を含めません。

## Consequences

本文の検証範囲は後続の [ADR 0047](0047-minimize-cli-request-body-validation.md) で見直しました。ID などの重複検証は削除し、この ADR の共通ゾーン検証は維持します。

共通仕様の変更を各リソースへ個別に反映する必要がなくなります。JSON 内の Zone も検証するため、フラグだけの検証では発生する抜けを防げます。設定で有効化していない操作と IaaS 以外の生成結果には影響しません。

フラグの指定有無を調べる既存の必須チェックは維持します。Switch の空文字列に対する表示は `--zone が必要です` から共通メッセージへ変更します。操作の公開範囲と API 呼び出しの動作は変更しません。

## Alternatives considered

- `--zone` フラグの解析時に検証する方法は、JSON 経路の Zone を検証できないため採用しません。
- フラグ名から検証を自動で追加する方法は、リクエストの型や単一ゾーンの制約を設定から読み取りにくくなるため採用しません。
- 各 `request_validator` から共通関数を呼ぶ方法は、同じ呼び出しを各リソースに残し、共通仕様の適用漏れを防ぎにくいため採用しません。
