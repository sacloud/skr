# ADR 0027: AppRun Dedicated API コマンドを手書きで実装する

- Status: Accepted
- Date: 2026-10-06

## Context

AppRun Dedicated SDK `v0.3.0` はクラスタ、アプリケーション、バージョン、オートスケーリンググループ、ワーカノード、ロードバランサ、証明書、サービスクラスの API 操作を公開しています。CLI ではこれらを単純な CRUD にまとめず、ページング、階層 ID、秘密情報を含み得るリクエスト、アプリケーションの有効バージョン切り替えなど、各操作の入力と出力を保つ必要があります。

## Decision

- `internal/apprundedicatedapi` に Kong コマンドと SDK 操作への接続を手書きで実装します。Ogen 系 API の共通生成器は使いません。
- SDK v0.3.0 の公開操作をリソース階層で公開し、各操作の入力、戻り値、ID 関係を維持します。ページング操作は `items` と `nextCursor` を含む出力にします。
- 複雑なリクエストは `--request` JSON で受け付けます。証明書 PEM やレジストリ認証情報など秘密情報を含み得る入力は、`@path.json` または標準入力からのみ読み込みます。
- sakumock を使い、実際の CLI コマンドパスから SDK の操作、ヘルプ、リクエスト／レスポンスを検証します。
- is1b のライブ E2E と利用者向けチュートリアルは別タスクとして後続対応します（[#59](https://github.com/sacloud/skr/issues/59)）。

## Consequences

- CLI は SDK の操作ごとの入力と戻り値を保ち、サービス固有の出力整形や秘密情報の取り扱いを追加できます。
- SDK の API モデル変更時はコマンド実装と sakumock テストを確認する必要があります。
- この決定ではライブ環境の動作確認と利用者向けチュートリアルを扱いません。後続タスクでライブ環境の費用、安全なクリーンアップ、確認済みの仕様を踏まえて対応します（[#59](https://github.com/sacloud/skr/issues/59)）。

## Alternatives considered

- 共通 API 生成器で一括生成する方法: ページング出力、秘密情報の入力制約、アプリケーションの有効化など、操作固有の挙動が共通設定だけでは表現しにくいため採用しません。
- 作成・参照・削除だけを提供する方法: バージョンの作成・有効化とワーカノードの状態確認まで含む運用経路を検証できないため採用しません。
