# ADR 0035: IaaS API のタグ配列を `--tags` で指定する

- Status: Accepted
- Date: 2026-10-09

## Context

IaaS API のリソースには `Tags` 配列があります。`--request` または個別フラグを使える操作でも、タグを指定するには JSON が必要でした。一方、`--request` と個別フラグの併用は ADR 0007 で禁止しており、複雑な入力を必要とする操作では引き続き JSON を使う必要があります。

## Decision

- IaaS API のトップレベル `Tags` 配列は、個別フラグ入力に対応している操作で `--tags` フラグからも指定できます。値は `production,web` のようなカンマ区切りです。
- `--tags` は SDK リクエストの `Tags` フィールドへ文字列配列として設定します。検索・作成・更新の各操作で同じフラグ表記を使います。
- JSON 入力では従来どおり `Tags` 配列を指定できます。`--request` と `--tags` を含む個別フラグは併用できず、値をマージしません。
- 個別フラグ入力を提供しない JSON 専用操作は JSON 専用のままにします。タグだけを `--request` に合成する例外は設けません。
- `Names`、`Sort`、`Disks`、`NetworkInterfaces` など、タグ以外の配列や複雑な値は JSON 入力に残します。

## Consequences

- Server と Switch の検索・作成・更新、Disk の検索で `--tags` を利用できます。Disk の作成・更新など複雑な JSON 専用操作では、従来どおり `--request` 内の `Tags` 配列を使います。
- 既存の JSON 入力と `--request`・個別フラグ間の相互排他は維持されます。更新時は `--tags` の省略を未指定として扱い、指定した場合は SDK リクエストの `Tags` フィールドを設定します。
- IaaS コマンド生成器はカンマ区切り文字列フラグを Go の文字列スライスへ変換し、SDK の公開リクエスト型に渡します。

## Alternatives considered

- `Tags` も JSON 専用にする方法: タグだけを指定する一般的な操作でも JSON が必要になるため採用しません。
- JSON と `--tags` の併用を許可してリクエストをマージする方法: 入力経路の相互排他に関する ADR 0007 の決定を崩し、JSON 内の `Tags` との優先順位も必要になるため採用しません。
- すべての配列をフラグ化する方法: 複雑な条件や配列をフラグへ展開することは入力方針の範囲外であるため採用しません。
