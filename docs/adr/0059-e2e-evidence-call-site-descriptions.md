# ADR 0059: E2E 証跡レポートの説明を呼び出し元に記述する

- Status: Accepted
- Date: 2026-10-26

## Context

E2E の証跡レポート (`REPORT.md`) は実行コマンドと応答を記録するだけで、シナリオの意図や各ステップで何を確認したのかを読み取れませんでした。当初はステップ説明を中央のレジストリに集約し、シナリオ情報は Recorder 生成後の setter (`SetScenario`) で登録する設計を検討しました。しかし中央レジストリは、ステップを変更するたびに呼び出し元とは別の場所も編集する必要があり、保守性を損ないます。setter もシナリオ情報の登録忘れが発生し得ます。

## Decision

- ステップ単位の確認内容は、`s.client.call(...)` の呼び出し元で `RecordWithDescription` / `RecordExpectedErrorWithDescription` に渡します。説明を中央のレジストリに集約しません。
- シナリオ単位のタイトルと目的は、`evidence.Scenario` として `New` / `CreateAt` のコンストラクター引数で渡します。`SetScenario` は廃止します。
- レポートはシナリオの節、ステップ一覧表 (`#`、ステップ、確認内容、結果、Exit status)、ステップごとの詳細で構成します。説明が未登録のステップは `(説明未登録)` と表示します。
- `Record` / `RecordExpectedError` は後方互換のため説明なしのシグネチャで維持します。
- 私的な証跡としての JSON ファイルと `ORDER.txt` の出力は従来どおり維持します。
- この方針は `test/e2e/internal/evidence` と全 runner に適用します。`AGENTS.md` の「E2E の配置と命名」や [ADR 0058](0058-live-e2e-command-coverage.md) の配置・命名ルールは変更しません。

## Consequences

- ステップを変更するときは、その呼び出し元だけを編集すればよくなります。
- 説明がコード上の実行位置に寄るため、レポートとコードの対応を追いやすくなります。
- 未登録の説明が `(説明未登録)` と可視化されるため、追加漏れに気付けます。
- 呼び出し元の引数に説明が加わるため、呼び出し行が長くなります。

## Alternatives considered

- ステップ説明を中央の map / switch レジストリに集約する案は採用しません。ステップの変更に呼び出し元とは別の編集が必要になり、保守性を損なうためです。
- `SetScenario` の setter を維持する案は採用しません。シナリオ情報の登録が Recorder 生成後の別呼び出しになり、登録忘れや確定タイミングの曖昧さを残すためです。
- 説明を JSON 記録だけに残しレポートへ出力しない案は採用しません。レポート単体でテストの意図と各ステップの確認内容を把握できることが目的のためです。
