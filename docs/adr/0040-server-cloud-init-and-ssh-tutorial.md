# ADR 0040: Server の cloud-init と SSH 接続チュートリアル

- ステータス: 承認済み
- 日付: 2026-10-13

## 背景

従来の Server チュートリアルは、OS を起動せず、サーバへの接続も行わずに作成するだけでした。生成された Server Create のフラグでは、cloud-init 対応イメージと共有セグメント NIC に必要なディスクや NIC の構成を表現できません。また、SDK では cloud-init の user-data を Server Boot 操作で渡します。

## 決定

Server Create は手書きのコマンドとして維持し、既存の `--request` 入力も引き続き利用できるようにします。cloud-init アーカイブ、ディスクプラン、ディスクサイズ、NIC を個別に指定するスカラーオプションを追加し、これらから API のディスクおよび NIC のフィールドを組み立てます。ディスク設定の一部だけが指定された場合や、`--request` と個別フラグが併用された場合はエラーにします。

手書きの Server Boot コマンドを追加します。user-data は `@path` または `-` でのみ受け付け、cloud-config の内容をプロセス引数に渡しません。チュートリアルでは SSH 鍵をローカルに作成し、その公開鍵を cloud-init の設定へ加えます。その後、サーバを起動して共有 NIC 経由で接続し、サーバとディスクを削除します。

## 影響

- Server の共通操作は生成コードのまま維持し、Create と Boot は Server 固有の手書きハンドラーで処理します。
- Create のオプションは cloud-init ディスクと NIC の指定に対応します。それ以外の API フィールドは引き続き JSON 入力で指定できます。
- チュートリアルでは、対象ゾーンで利用できるアーカイブとディスクプランが必要です。リソースを削除するまで利用料金が発生します。
- SSH の秘密鍵はローカルに保持します。CLI は保護されたファイルまたは標準入力から user-data を読み込み、インライン入力は受け付けません。
- is1b のライブ E2E runner で作成、起動、SSH ログイン、削除を検証します。runner は自身が作成していないリソースを削除しません。

## 検討した選択肢

- Create の入力をすべて `--request` にする案: このユースケースでは説明的なオプションを使うチュートリアルにするため採用しません。
- 汎用的なネストフィールド用フラグ機構を追加する案: ディスクと NIC は構造化された配列であり、今回必要な Server の手順に対して過剰なため採用しません。
- Server Create で user-data を渡す案: SDK では別の Boot 操作で適用するため採用しません。
- 秘密鍵を API に渡す案: ゲストが必要とするのは対応する公開鍵のみのため採用しません。
