# ADR 0087: --query-raw フラグで文字列の生出力に対応する

- Status: Accepted
- Date: 2026-11-17

## Context

[ADR 0025](0025-jq-output-filter.md) で導入したグローバル `--query` は、クエリ結果を常に JSON として出力します。文字列のスカラー値は引用符付きで出力されるため、検索結果の ID をシェル変数へ取り込むには `jq -er '.'` でのデコードが必要でした。チュートリアルの ID 取得手順では `--query '...' | jq -er '.'` が頻出し、ID の受け渡しにだけ外部 jq コマンドへの依存が発生していました ([#267](https://github.com/sacloud/skr/issues/267))。

## Decision

- グローバル `--query-raw` を追加します。`--query` と同じ gojq の式評価を行い、結果ごとの出力だけが異なります。
- `--query-raw` の出力は jq の `-r` (`--raw-output`) に準拠します。文字列の結果は引用符なしの生文字列で出力し、文字列以外 (null、数値、真偽値、配列、オブジェクト) は `--query` と同じ JSON 出力になります。複数の結果は 1 行に 1 件、0 件は空出力で終了コード 0 です。
- `--query` と `--query-raw` は同時に指定できません。kong の `xor` タグで相互排他にし、API 呼び出し前に拒否します。
- `--query-raw` は `--query` と同じコマンドに適用されます。JSON 以外の出力を持つコマンド (`skr apprun-dedicated` の diff、delete など) は `--query` と同様に `--query-raw` もエラーにし、レスポンス本文をそのまま扱う `skr http` と `skr secretmanager-api unveil-secret` では `--query` と同様に適用しません。

## Consequences

- チュートリアルの ID 取得手順から `| jq -er '.'` を外せます。文字列の抽出に外部 jq コマンドは不要になります。
- 文字列以外の抽出や加工には引き続き外部 jq を使えます。`--query-raw` は文字列を生出力にするだけで、jq の `-e` (結果の有無による終了コード制御) は提供しません。
- クエリ結果を JSON として出力する [ADR 0025](0025-jq-output-filter.md) の方針は `--query` で維持します。既存の `--query` の挙動は変わりません。
- クエリ系フラグが 2 つになるため、指定の読み取りとエラーメッセージのフラグ名を `internal/cli` の共通処理で扱います。`--query` がルート共通フラグのため生成コードへの影響はありません。

## Alternatives considered

- `--raw-output` のような boolean フラグを `--query` に追加する方法: jq のオプション構造に近いですが、ID の抽出に 2 つのフラグの指定が必要になります。チュートリアルの記述を 1 つのフラグにまとめられる `--query-raw` を採用します。
- `--query` の結果を常に生出力にする方法: オブジェクトや配列の抽出で既存の利用者の期待 (JSON 出力) と異なるため採用しません。
- jq の `-e` の挙動も含めて提供する方法: 結果が空や null の場合の終了コード制御は現時点で要望がなく、出力の生出力と終了コードの意味を分けたほうが単純なため範囲にしません。必要になったときに別途検討します。
