# ADR 0008: IaaS 検索で全ゾーンを指定する

- Status: Accepted
- Date: 2026-10-05

## Context

IaaS API の検索操作は通常、`Zone` に単一のゾーン名を指定します。複数ゾーンを対象に同じ条件で検索する場合、ユーザーがゾーンごとにコマンドを繰り返して結果をまとめる必要があります。`all` の解釈を各リソースで別々に実装すると、ページ指定やエラー時の挙動が不統一になります。

## Decision

- IaaS API のゾーン指定を受け取る検索操作では、個別フラグの `--zone all` を指定すると SDK の公開 Zone API でゾーン一覧を取得し、その検索操作を各ゾーンに対して実行して結果を連結します。
- ゾーン一覧の順序を保ちます。SDK の検索条件 `Count`、`From` などはゾーンごとの検索呼び出しに適用します。
- ゾーン一覧の取得またはいずれかのゾーン検索に失敗した場合は、部分結果を標準出力へ返さず、エラーにします。
- `all` は検索操作のフラグ経路だけで使います。`--request` の JSON は従来どおり処理し、`all` による特別な処理を追加しません。`read`、作成、更新、削除では個別フラグの `--zone all` を API 呼び出し前に拒否します。
- 共通のゾーン列挙・集約ヘルパーを利用し、各検索コマンドは自身の SDK 公開操作を呼び出します。最初の適用対象は `skr iaas-api switch find` です。

## Consequences

- Switch の `find` は一度のコマンドで全ゾーンの検索結果を取得できます。結果形式は従来どおり SDK の Switch 配列です。
- 検索条件の `Count` と `From` は全ゾーンを通した合計値ではなく、各ゾーンの API 呼び出しごとに適用されます。
- `all` は複数ゾーンへの変更操作を意味しません。将来の IaaS 検索コマンドも共通ヘルパー、操作ヘルプ、テスト、関連ドキュメントを更新して対応します。
- 全ゾーン検索ではゾーン一覧を取得してから各ゾーンの API を呼び出すため、単一ゾーン検索より多くの呼び出しが発生します。

## Alternatives considered

- ゾーンごとに手動で検索してもらう方法: コマンドごとに操作を繰り返す必要があり、要望を解決しないため採用しません。
- `all` を CRUD 操作にも適用する方法: 対象が複数になり得る変更操作の意味が曖昧で、意図しない変更につながるため採用しません。
- `all` を `--request` の JSON にも展開する方法: 今回の要望は簡潔な `--zone all` を使った検索で満たせるため、対応範囲を広げず採用しません。
- エラーになったゾーンを飛ばして部分結果を返す方法: 不完全な検索結果が成功に見えるため採用しません。
