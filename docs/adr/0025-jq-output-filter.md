# ADR 0025: API 出力を jq 式で加工する

- Status: Accepted
- Date: 2026-10-06

## Context

API コマンドの JSON、YAML、table 出力は、利用者が必要なフィールドだけを選んだり、一覧を条件で絞り込んだりする機能を持ちません。JMESPath ではなく、jq 式による加工を提供します。

## Decision

- API の結果加工用にグローバルな `--query` を追加し、jq 式で出力を変換します。
- 評価器には Go 実装の gojq を使い、jq コマンド本体を実行環境の依存にしません。
- `--query` を指定した場合、`--output` とプロファイル既定の出力形式は無視し、複数のクエリ結果は JSON として順に出力します。クエリ結果が空の場合は何も出力しません。
- `--query` は API コマンドの結果に適用し、レスポンス本文をそのまま扱う `skr http` には適用しません。

## Consequences

- jq 式でフィールド選択、配列の展開、条件による絞り込みなどを行えます。
- クエリ結果は JSON であるため、従来の `--output yaml` や `--output table` はクエリ指定時には適用されません。
- gojq は jq の Go 実装であり、jq 本体と一部の機能や動作に差異があります。利用者向けガイドから gojq の互換性情報を参照します。

## Alternatives considered

- JMESPath を採用する方法: Issue #48 で jq 式を選択する方針としたため採用しません。
- システムの jq 実行ファイルを子プロセスとして呼び出す方法: 環境ごとの jq インストールを必要とするため採用しません。
- クエリ結果を YAML や table にも出力する方法: jq 式は任意の形状・複数の出力値を返せるため、JSON 値として出力する方式を採用します。
