# ADR 0007: API リクエストにフラグと JSON の2つの入力経路を設ける

- Status: Accepted
- Date: 2026-10-05

## Context

低レベル API コマンドは SDK のリクエスト型を `--request` の JSON で受け取れます。しかし、Switch の作成に必要な `Zone` と `Name` のような少数の値を渡すたびに JSON ファイルやシェルでの引用符が必要になると、手動操作とチュートリアルが読みにくくなります。一方、入れ子の設定や省略と `null` を区別するフィールドをすべてフラグ化することも適切ではありません。

## Decision

- SDK リクエストを受け取る `<domain>-api` の操作では、フラグだけで有効な最小リクエストを表せる場合、操作固有の名前付きフラグを提供します。必要な値がトップレベルの独立した単一スカラー値であることを条件とし、件数には上限を設けません。独立して指定でき、省略時の意味を維持できる任意の単一スカラー値も対象にします。入力不要の操作や位置引数だけを使う既存の操作は変更しません。詳細な判定手順は[コマンド作成スキル](../../.agents/skills/generate-skr-api-command/SKILL.md)に記載します。
- 複雑なオブジェクト、入れ子の設定、配列、nullable な値、秘密情報など、フラグでは表現しにくい入力は既存の `--request` で扱います。例外として、IaaS API のトップレベル `Tags` 配列は個別フラグ入力に対応する操作で `--tags` によるカンマ区切り指定をサポートします。詳細は [ADR 0035](0035-iaas-tags-flag.md) を参照してください。対応済みの JSON 入力形式を維持し、任意の SDK リクエストを渡せる経路を残します。秘密情報はコマンドライン引数に含めず、保護したファイルまたは安全な標準入力経由で扱います。
- `--request` と個別フラグは相互排他とします。両方を指定した場合はエラーにし、JSON とフラグを暗黙にマージしません。どちらの経路でも同じ SDK のリクエスト型と呼び出しを使用し、必須値の欠落や型の誤りは明示的に報告します。
- 任意フラグでは、未指定と明示的な `false`、`0`、空文字列などを区別します。更新でフィールドを省略すると変更しない場合、その意味を維持します。値のクリアや `null` の指定は、SDK の意味を確認したうえで JSON 経路に残します。
- フラグの名称、型、相互排他、必須条件と利用例を操作の `--help` に記載します。チュートリアルは実装済みのフラグで簡潔に書ける場合にそれを優先し、複雑な入力は JSON ファイルを使用します。未実装のフラグを先行して例示しません。

## Consequences

- SDK v0.3.0 の Switch `CreateRequest` には7フィールドあり、`Zone` と `Name` が必須です。Server の作成には20フィールド、Disk の作成には18フィールドあり、任意値や複雑な型も含まれます。Database の作成には33フィールドあり、配列、秘密情報、条件付きの必須値も含まれます。フィールド総数や検証タグの数でフラグ経路を決めません。
- Switch では作成時の zone と name、参照・削除時の zone と ID などをフラグ化します。検索の `Names` と `Tags`、作成・更新の `Tags` など配列は JSON 経路に残します。ただし、IaaS のトップレベル `Tags` は [ADR 0035](0035-iaas-tags-flag.md) により `--tags` でも指定できます。単純な操作のチュートリアルにはフラグを使用します。
- 新しい API 操作ごとに、フラグと JSON が同じ SDK リクエストに至ること、必須値、相互排他、未指定と明示的なゼロ値、エラー表示をテストします。既存操作にフラグを追加する場合も JSON 経路を維持します。
- 入力経路が2つになるためヘルプとテストの保守が増えますが、簡単な手動操作と複雑な API リクエストの双方を扱えます。

## Alternatives considered

- JSON だけを受け付ける方法: 少数の値を渡す操作でも記述が煩雑になるため採用しません。
- すべての SDK フィールドをフラグ化する方法: 入れ子の設定、省略と `null`、秘密情報の扱いが複雑になるため採用しません。
- フィールド数でフラグ経路を制限する方法: 多数の任意フィールドがある操作でも単純な最小リクエストを作れるため採用しません。
- JSON にフラグを上書きしてマージする方法: 優先順位と部分更新時の意味が曖昧になるため採用しません。
