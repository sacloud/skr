# ADR 0041: Server Create のディスクと NIC を反復可能な構造化オプションで指定する

- ステータス: 承認済み
- 日付: 2026-10-14

## 背景

Server は複数のディスクを持てます。ADR 0040 で追加した `--cloudimg-archive-id`、`--disk-plan-id`、`--disk-size-gb` はディスク1個だけを表し、複数指定に拡張すると設定の所属が曖昧になります。一方、cloud-init の起動手順では、リクエスト全体を JSON で記述せずに実行したいという要件があります。

ADR 0007 と ADR 0035 では、複雑な値や配列を JSON 入力に残しています。ディスクの個別フラグはこの方針の例外となるため、対象と入力形式を明示する必要があります。

## 決定

Server Create に反復可能な `--disk` と `--nic` オプションを設けます。1回の指定をディスクまたは NIC の1個に対応させ、指定順に API の `Disks` と `NetworkInterfaces` 配列を組み立てます。値はカンマ区切りの `key=value` 形式とします。

```console
$ skr iaas-api server create --zone is1b --name example --cpu 1 --memory-gb 1 \
    --disk 'archive-id=123,plan-id=4,size-gb=20' \
    --disk 'plan-id=4,size-gb=100' \
    --nic 'upstream=shared' \
    --nic 'upstream=disconnected'
```

アーカイブ ID は仮の値です。

- 初期の対応キーは `archive-id`、`plan-id`、`size-gb` とします。`plan-id` と `size-gb` は各ディスクで必須とし、`archive-id` を省略した場合は空のディスクを作成します。接続方式は virtio とします。
- NIC の初期の対応キーは必須の `upstream` とし、`shared` または `disconnected` を受け付けます。スイッチ ID など、それ以外の構成は JSON 入力に残します。
- 各 ID とサイズは正の整数を受け付けます。API で利用可能なプラン、サイズ、アーカイブの組み合わせであることは別途確認する必要があります。
- 未知のキー、同じ指定内での重複キー、空の値、空の要素、不正な構文、必須キーの欠落はエラーにします。入力を暗黙に補正したり、重複キーを上書きしたりしません。
- 初期の対応値は整数と上記の列挙値だけとし、引用符やエスケープを解釈する独自機構は設けません。自由文、秘密情報、さらにネストした値は受け付けません。
- `--request` と `--disk` を含む個別フラグは相互排他とし、JSON とのマージは行いません。その他のディスク構成は引き続き `--request` で指定します。
- ADR 0007 と ADR 0035 の JSON 入力方針に対し、Server Create の上記ディスクと NIC の指定だけを例外とします。他の配列を一般的にフラグ化する決定ではありません。
- ADR 0040 のディスク用の3フラグと `--network-interface` は、これらのオプションへ置き換えます。

## 影響

ディスクごとの設定を1つの値にまとめることで、単一ディスクと複数ディスクに同じ構文を使えます。ただし、独自の構文解析と検証が必要です。手書き処理の正常系とエラー系は、ドメインパッケージの単体テストで検証します。

実装時にはヘルプ、チュートリアル、ライブ E2E runner、設計文書を新しい構文に合わせて更新します。

## 検討した選択肢

- ディスク用の3フラグを維持する案: 複数ディスクを指定するときの所属を表現できないため採用しません。
- `--disk` ごとに JSON を指定する案: 独自構文は不要ですが、少数の整数を指定する手順としては読みにくいため採用しません。
- リクエスト全体を `--request` にする案: 複雑な構成用の入力経路として維持しますが、今回の簡便な手順には採用しません。
- すべてのネストフィールドに対応する汎用フラグ機構を作る案: 対象範囲と検証が広がりすぎるため採用しません。
