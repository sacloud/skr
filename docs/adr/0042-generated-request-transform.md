# ADR 0042: 生成コマンドに反復可能な入力と型付きリクエスト変換を接続する

- ステータス: 承認済み
- 日付: 2026-10-14

## 背景

Server Create の反復可能な `--disk` と `--nic` は、[ADR 0041](0041-server-repeatable-disk-and-nic-options.md) に従って配列要素を構築します。従来の `handwritten: true` はコマンド構造体と `Run` 全体の生成を省略するため、入力変換だけでなく、スカラーフラグ、JSON 入力、相互排他、検証、API 呼び出し、出力も手書きで複製していました。この構成では、ヘルプの維持や標準処理の変更時に差異が生じやすくなります。

[#104](https://github.com/sacloud/skr/issues/104) では、入力変換だけを手書きに残す拡張点と、反復可能な `key=value` 入力の解析まで生成器に持たせる案を検討します。

## 決定

生成器に `repeated_flags` と `request_transform` を追加します。生成器は入力の収集と標準処理を担当し、入力の意味とリクエストへの変換はドメインパッケージに残します。

- `repeated_flags` はフラグ名、コマンドフィールド名、ヘルプを明示します。生成するフィールドは `[]string` とし、Kong の `sep:"none"` で1回の指定を1要素として保持します。カンマで分割したり、空の指定を除去したりしません。
- `request_transform` は Runtime に生成する公開 callback フィールド名です。関数型は `func(*操作コマンド型, *リクエスト型) error` とし、CLI 側から同じドメインパッケージの手書き関数を接続します。名前文字列と `any` による実行時の振り分けは追加しません。
- 反復入力の指定有無も `--request` との相互排他に含めます。空文字列を明示した場合も指定済みとして扱い、JSON とフラグをマージしません。
- 変換はフラグ経路だけで実行します。必須フラグの確認と標準フィールドの代入後、既存のリクエスト検証と API 呼び出しの前に1回実行します。反復入力が未指定でも、フラグ経路では設定済みの変換を呼びます。
- JSON 経路は変換を通さず、従来どおりデコード後にリクエスト検証へ進みます。callback が未接続の場合と変換エラーの場合は、フラグ経路をエラーで終了し、API を呼びません。
- 反復入力には `request_transform` を必須とします。生成対象でない操作、不正な識別子、フラグ名やフィールド名の衝突、Runtime callback 名の衝突、生成型名の衝突を設定検証で拒否します。callback の接続先や API フィールドの型との一致は再生成後のビルドで確認します。

Server Create はコマンド構造体と `Run` を生成し、ディスク／NIC の解析と固有制約だけを `serverapi.TransformCreateRequest` に残します。Boot のファイル／標準入力処理は、この反復入力の拡張に合わせて一般化せず、手書きを維持します。

## 影響

標準処理とヘルプの設定を生成器へ戻し、手書き部分の重複を減らせます。必須フラグ不足のエラーは、他の生成操作と同様に最初に不足したフラグを個別に示します。既存の入力形式、JSON 経路、ディスクと NIC の順序、固有制約は維持します。

生成器は、対応キー、必須キー、整数の範囲、列挙値、要素間の制約を知りません。これらと、入力値をエラーへ含めない方針はドメイン側で実装・検証します。ヘルプも各入力の仕様を明示し、ドメイン処理との一致をテストします。

これは任意の API 配列をフラグ化する決定ではありません。[ADR 0007](0007-api-request-input.md) と [ADR 0035](0035-iaas-tags-flag.md) の入力方針を維持し、Server の限定例外には ADR 0041 を適用します。秘密情報を反復可能な引数として受け取る用途には使いません。

## 検討した選択肢

- `key=value` の解析と制約まで宣言的に生成する案: 対応キー、型、既定値、別フィールドからの値の補完、要素間の制約など設定の責務が広がります。現時点では Server 固有の解析を残し、共通化する必要が確認できるまで採用しません。
- 任意の前処理を `any` で接続する案: 型の誤りを実行時まで検出できないため採用しません。
- Server Create 全体を手書きにする案: 固有の入力変換だけのために標準処理を複製する負担が大きいため採用しません。Boot など生成が適さない操作は手書きを維持します。
