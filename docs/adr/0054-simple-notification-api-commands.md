# ADR 0054: Simple Notification API コマンドを追加する

- Status: Accepted
- Date: 2026-10-20
- SDK: `github.com/sacloud/sacloud-sdk-go v0.3.1`

## Context

Simple Notification はメールや Webhook を使って通知を送信するサービスです。SDK には通知先、通知先グループ、ルーティング、通知履歴の操作が公開されていますが、CLI から利用できませんでした。通知先の設定にはメールアドレスや Webhook URL が含まれ、通知送信は外部への副作用を伴います。

## Decision

- `simple-notification-api` を追加し、通知先、通知先グループ、ルーティング、通知履歴の各操作を公開します。操作範囲は [`docs/design/simple-notification-api.md`](../design/simple-notification-api.md) に記録します。
- Ogen 系 API の共通生成器を使い、生成設定を `api/commands/`、生成コードとドメイン固有処理を `internal/simplenotificationapi/` に配置します。CLI の登録と SDK 接続は `internal/cli/` が担当します。
- 通知先の作成リクエストは `--request @path.json` に限定します。通知先設定を含む更新も `@path.json` を必須とし、メールアドレスや Webhook URL をコマンド引数に出しません。通知先の設定を含まないメタデータ更新では、既存の JSON 入力経路を維持します。
- API リクエストに含まれる単純な `Message` は `--message` で指定できます。`--request` と `--message` は相互排他とし、暗黙にマージしません。
- 通知送信は実際の通知を発生させる操作としてヘルプと文書で明示します。送信 API の成功応答は受け付けを表し、通知先への到達完了を保証しません。送信処理の状況は通知履歴で確認します。
- 確認フラグ付きライブ E2E runner を用意します。既存の有効な通知先を使い、一意な一時グループを作成して通知を1件送信し、履歴の送信処理完了を確認した後、一時グループだけを ID と設定内容で照合して削除します。作成結果から ID を得られない場合は推測で削除せず、手動確認を要求します。ライブ E2E は利用者の明示的な承認なしに実行しません。
- 送信を伴わない追加検証には runner の `--crud-only` を使います。既存のメール通知先と同じアドレスの一時通知先、一時グループ、一時ルーティングだけを作成・更新・削除し、設定の保持と変更を読み戻して確認します。並べ替え対象は未使用の順位に移動する一時ルーティングだけとし、既存設定の不変も照合します。

## Consequences

- 利用者は CLI から通知先、グループ、ルーティング、履歴の操作とグループへの通知送信を行えます。
- 通知先のアドレスを含む入力は保護されたファイルから読み込む必要があります。通知先作成や設定を含む更新のインライン JSON は受け付けません。
- 通常のライブ E2E は実際の通知を送信します。API の受付結果と通知履歴の送信処理状態を検証しますが、メールや Webhook の最終到達は保証しません。`--crud-only` はテスト通知を送りません。通知先登録時には確認メールを受信することがあります。

## Alternatives considered

- 通知先の値を `--request='...'` で受け付ける案: 値がシェル履歴やプロセス引数に残るため採用しません。
- 通知先のメールアドレスや Webhook URL を個別フラグにする案: 秘密情報をコマンド引数として扱うため採用しません。
- 通知 API の成功応答だけでライブ E2E を成功とする案: 受付応答は送信先への到達や送信処理完了を示さないため採用しません。
- 作成応答から ID を取得できない場合に、名前や説明で検索して削除する案: 同名・同設定の別リソースを誤削除する可能性があるため採用しません。
