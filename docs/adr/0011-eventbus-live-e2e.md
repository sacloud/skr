# ADR 0011: EventBus の実機イベント配送を E2E で検証する

- Status: Accepted
- Date: 2026-10-05

## Context

`eventbus-api` の実装時点では skr に Switch と SimpleMQ の API コマンドがなく、EventBus のトリガーから実際のスイッチ作成イベントを配送する経路を CLI で一貫して検証できませんでした。また、ライブ E2E を実装する方針もまだありませんでした。現在は `iaas-api switch` と `simplemq-api` があるため、イベントの発生からメッセージ受信までを実機で検証できます。

EventBus は実イベントの検知とジョブ配送を伴うため、sakumock による API 操作テストだけでは全経路を確認できません。実機試験はスイッチ、キュー、実行設定、トリガーを作成し、確実な後片付けを必要とします。

## Decision

- `test/e2e/eventbus-api` にビルド済み skr CLI を操作する Go E2E を置きます。SimpleMQ キュー、EventBus 実行設定とトリガーを作成し、`is1b` に通常スイッチを作成して、設定したメッセージを SimpleMQ から受信できることを確認します。
- ライブ実行には `--confirm-is1b-live` を必須とします。実行前に選択中プロファイルを確認し、同名リソースがあれば変更せずに中止します。名前と説明には試験専用のランダム識別子を使います。
- 作成結果の ID と名前・説明を再照合してから削除します。作成応答が不確定な場合は一覧から完全一致する試験専用リソースだけを特定し、トリガー、実行設定、スイッチ、キューの順に削除します。識別できないリソースは削除しません。
- SimpleMQ API キーはアクセス制限した一時ファイルに保存します。API キーを含む rotate の出力は証跡から除外します。操作証跡は Git worktree 外のアクセス制限付き一時ディレクトリに保存し、手動で削除するまでは実機リソースの調査に使えるよう残します。
- トリガーを読み戻して ID、名前、説明を確認した後、反映待ちとして60秒待ってからテストイベントを発生させます。
- EventBus のイベント配送はベストエフォート型であり、即時実行を保証しません。E2E は最大5分間メッセージをポーリングし、期限内に届かなければ失敗として扱って作成済みリソースの後片付けを試みます。

## Consequences

- Switch、SimpleMQ、EventBus を組み合わせた CLI 経路と、実イベントの検知からキュー配送までを再実行できます。
- 実行には対象プロジェクトで必要な API 権限と、`is1b` でのスイッチ作成・削除を含む明示的な承認が必要です。
- EventBus の実機イベント処理は外部の変更や遅延に影響されます。実行環境にない CI ではライブ E2E を自動実行せず、ローカルの fake CLI テストでシナリオと後片付けを検証します。
- SimpleMQ の配送成功は確認しますが、シンプル通知の配信先到達やメール・Webhook はこの E2E の検証対象外です。

## Alternatives considered

- EventBus、Switch、SimpleMQ の各 API 操作を個別の unit test だけで検証する方法: EventBus による実イベント検知と配送は再現できないため採用しません。
- 共用の固定リソースを使う方法: 他のテストや利用者のリソースを変更する危険があるため採用しません。
- 既存の Switch または SimpleMQ E2E にイベント配送を含める方法: 複数サービスのライフサイクルと権限を分離して理解できるよう、専用の EventBus E2E とします。
