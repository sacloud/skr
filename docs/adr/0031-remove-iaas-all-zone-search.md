# ADR 0031: IaaS の全ゾーン検索を廃止する

- Status: Accepted
- Date: 2026-10-08

## Context

[ADR 0008](0008-iaas-search-all-zones.md) では、`--zone all` を指定した検索で Zone API からゾーン一覧を取得し、各ゾーンに検索を繰り返して結果を連結する仕様を決めました。その後、[ADR 0030](0030-remove-table-output.md) により出力形式を JSON のみに統一しました。以前は table の先頭列にゾーン名を表示できましたが、JSON では SDK が返すデータ形状を変えずに検索結果の所属ゾーンを示す方法が定まりません。

全ゾーン検索では、ゾーン一覧を取得した後、対象リソースの検索 API を各ゾーンに呼び出します。現在のゾーン数では許容できても、ゾーンや専有ゾーンなどの選択肢が増えると、利用者の意図しない呼び出しが増えます。また、生成器、CLI の初期化、検索結果の集約、失敗時の部分出力抑止、テストとドキュメントにまたがる実装が必要です。

この決定は、ADR 0030 の「結果集約を維持する」項目と [ADR 0019](0019-generate-non-iaas-api-commands.md) の IaaS `zone_search` 設定に関する記述も置き換えます。それ以外の出力形式および生成器の決定は維持します。

[ADR 0017](0017-separate-iaas-api-generator-command.md) の Context では全ゾーン検索を IaaS 生成器の機能例に挙げていますが、この機能は本 ADR で廃止します。IaaS 専用の生成器入口を維持する決定は変わりません。

## Decision

- IaaS API コマンドから `--zone all` による全ゾーン検索を削除します。検索を含む各操作では対象ゾーンを明示します。
- `Zone` が `all` の場合、フラグと JSON のどちらも API の呼び出し前に拒否します。
- 生成器は `zone_search` 設定、ゾーン列挙、検索結果の集約を扱いません。CLI のリソース初期化では、全ゾーン検索用 Zone API factory を登録しません。
- `skr iaas-api zone find` はゾーン一覧の取得手段として維持します。CLI は複数ゾーンを検索せず、結果をまとめません。

## Consequences

- IaaS の検索操作は、単一ゾーンに対する API 呼び出しだけを行います。ゾーン数に比例する追加呼び出しは発生しません。
- `Zone: "all"` はフラグと JSON のいずれでも明示的な入力エラーになります。利用者は検索対象のゾーン名を指定します。
- JSON の出力形状に検索対象のゾーン情報を追加する必要がなくなり、SDK が返すデータ形状を維持できます。
- 生成コード、CLI 配線、検索集約ヘルパー、関連テストとドキュメントが簡素になります。

## Alternatives considered

- 全ゾーンの検索結果をゾーンごとのオブジェクトで包んで JSON 出力する方法: 既存の SDK レスポンス形状を変更し、利用者のクエリや自動処理の契約を追加するため採用しません。
- 各結果にゾーン名を付加する方法: SDK のレスポンスデータに CLI 固有の情報を混ぜるため採用しません。
- 既存の `--zone all` と呼び出し集約を維持する方法: JSON 出力でゾーン情報を表現する問題と、ゾーン数に応じて増える API 負荷、実装・テストの複雑さが残るため採用しません。
- ゾーンの反復を CLI 利用者に任せる方法: 全ゾーン検索を別の専用機能として設けず、必要なゾーンを利用者が明示する決定に含まれるため、CLI 側の追加対応は行いません。
