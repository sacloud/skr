# ADR 0004: Markdown の執筆規約と textlint の運用

- Status: Accepted
- Date: 2026-10-05

## Context

`make lint-text` は、日本語の箇条書きに「である」調を要求する一方、同じ文書の本文には「です・ます」調を要求する場合がある。この判定に合わせて箇条書きを書き換えると、文書内の文体が不統一になる。textlint の指摘には、実際の読みづらさを示すものと、製品文書に適さない機械的な判定が混在している。

## Decision

日本語の説明文は文書内で文体を統一し、原則として「です・ます」調を使う。箇条書きも本文と同じ文体にする。Markdown を追加・変更した場合は、コミット前に `make lint-text` を実行する。

箇条書きの文体を不自然に強制する `no-mix-dearu-desumasu` は textlint 設定で無効にする。その他の指摘は、読みやすさや正確さを損なわない範囲で文章を修正する。製品用語などへの誤検出は、文章の意味を変えて回避せず、必要なルールだけを設定で除外する。

運用ルールは既存の `AGENTS.md` に記載する。Lefthook は現時点で導入されておらず、追加の hook 管理ツールは導入しない。

## Consequences

- 箇条書きと本文の文体を揃えながら、意味のある技術文書のチェックを維持できる。
- コミット前チェックは開発者とエージェントの手順に依存し、Git hook による自動強制は行わない。
- `make lint-text` の実行には Docker が必要である。

## Alternatives considered

- `no-mix-dearu-desumasu` に合わせて箇条書きを「である」調に変更する: 本文と文体が不統一になるため採用しない。
- Lefthook を導入してコミット時に自動実行する: 既存の hook 管理がなく、実行に Docker を要する lint のために追加の導入・運用を増やさない。
