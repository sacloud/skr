# EventBus API ライブ E2E 設計

- ADR: [0011](../adr/0011-eventbus-live-e2e.md)
- 証跡保存先: [ADR 0012](../adr/0012-eventbus-evidence.md)

## 目的と範囲

`test/e2e/eventbus-api` は、EventBus のトリガーが通常スイッチ作成イベントを検知し、実行設定から SimpleMQ キューへメッセージを送るまでを実機で確認します。`eventbus-api` 実装当時は skr に Switch と SimpleMQ の操作がなく、また E2E を実装する方針も決まっていなかったため、実イベントを使った CLI 経路の再現はありませんでした。現在は両コマンドがあるため、スイッチ作成イベントを含むシナリオを1つの Go スクリプトで実行します。

シンプル通知のメール・Webhook などの到達性は検証しません。トリガーを読み戻した後、イベント設定が反映されるまで60秒待ってからスイッチを作成します。イベント配送はベストエフォート型のため、スクリプトは作成後最大5分間 SimpleMQ をポーリングします。

## 実行

ライブ API と `is1b` のスイッチを作成・削除するため、実行前に SDK プロファイルと対象プロジェクトを確認し、実行の承認を得てください。

```console
$ make build
$ ./skr config current
$ go run ./test/e2e/eventbus-api --skr ./skr --confirm-is1b-live
```

コマンドの実行証跡は `./tmp/eventbus-api/<YYYYMMDDHHmm>/` に保存され、開始時に実際の保存先が表示されます。同じ分に複数回実行した場合は `-02` 以降を付けて既存の証跡を上書きしません。

各 JSON ファイル名の先頭にある3桁の連番が実行順です。`test/e2e/internal/evidence` が共通の記録処理を提供し、`ORDER.txt` にも連番、操作名、成否、対応する JSON ファイルを記録します。`receive-event-message` のように同じ操作を繰り返す場合も、連番で順序を確認できます。`RESULT.txt` には最終結果を記録し、`REPORT.md` にはコマンド、stdout、stderr、終了コードと最終結果をまとめます。

スクリプトは一意な試験名を使い、SimpleMQ キュー、実行設定、トリガー、`is1b` の通常スイッチを作成します。トリガーは `//eventbus.sakura.ad.jp/eventlog` の `jp.ad.sakura.eventbus.eventlog.IaaS.request.Switch.normal.created` を対象とし、イベントの `zone` が `is1b` のときだけ実行設定を起動します。SimpleMQ から一意な試験メッセージを受信したことを確認します。

事前確認で既に試験名が使われている場合は中止し、既存リソースを削除しません。後片付けでは取得した ID、名前、説明を再確認してからトリガー、実行設定、スイッチ、キューの順で削除し、一覧からの消失を確認します。作成 API がエラーを返しても作成済みの可能性がある場合は、名前と説明が完全一致するリソースだけを探して回収します。確認できない場合は削除せず、手動対応が必要なエラーを返します。

## 秘密情報と証跡

SimpleMQ の API キーは権限 `0600` の一時ファイルに保存します。EventBus のシークレット登録用 JSON も同じく `0600` で保存し、実行終了時に両方を削除します。API キー発行コマンドの stdout は証跡に記録せず、`[REDACTED: APIKey]` に置き換えます。

コマンドの引数、出力、エラーは `.gitignore` 対象の `./tmp/eventbus-api/` 以下に記録します。実行ごとのディレクトリは `0700`、JSON 証跡と索引ファイルは `0600` です。証跡にはプロジェクト ID やリソース ID を含む可能性があるため、共有・コミットせず、確認後に削除してください。

E2E のシナリオ、既存リソース衝突時の中止、作成応答が不確定な場合の回収、API キー証跡の秘匿は `test/e2e/eventbus-api/main_test.go` の fake CLI テストで確認します。

## 実機確認

2026-10-05 に選択中の SDK プロファイルでライブ E2E を実行し、`is1b` のスイッチ作成イベント後に設定したメッセージを SimpleMQ キューから受信できることを確認しました。後片付け後にスイッチ、トリガー、実行設定、キューが残っていないことも確認しました。この実行の証跡は新しい保存先形式へ移行しており、`ORDER.txt` で操作順を確認できます。
