# EventBus API ライブ E2E 設計

- ADR: [0011](../adr/0011-eventbus-live-e2e.md)
- 証跡保存先: [ADR 0012](../adr/0012-eventbus-evidence.md)

## 目的と範囲

`test/e2e/eventbus-api` は、EventBus のトリガーが通常スイッチ作成イベントを検知し、実行設定から SimpleMQ キューへメッセージを送るまでを実機で確認します。`eventbus-api` 実装当時は skr に Switch と SimpleMQ の操作がなく、また E2E を実装する方針も決まっていなかったため、実イベントを使った CLI 経路の再現はありませんでした。現在は両コマンドがあるため、スイッチ作成イベントを含むシナリオを [ADR 0062](../adr/0062-e2e-testing-t-based-scenario.md) に従い testing.T ベースのシナリオテストで実行します。

シンプル通知のメール・Webhook などの到達性は検証しません。トリガーを読み戻した後、イベント設定が反映されるまで60秒待ってからスイッチを作成します。イベント配送はベストエフォート型のため、シナリオは作成後最大5分間 SimpleMQ をポーリングします。

## 実行

ライブ API と `is1b` のスイッチを作成・削除するため、実行前に SDK プロファイルと対象プロジェクトを確認し、実行の承認を得てください。

```console
$ make build
$ SKR_E2E=1 go test ./test/e2e/eventbus-api/ -run TestScenarioEventBus -v -timeout 25m
```

`SKR_E2E` を設定して `go test` を実行すると `skr-e2e` プロファイルでライブ実行し、通常の `go test` では実行環境を変更しません。実行記録は Git 管理外の `test/e2e/eventbus-api/e2e-output/` 配下に `eventbus-api-<実行日時>.md` の Markdown で保存され、レポートの先頭にシナリオ全体の所要時間と生成日時が記録されます。リソース ID や応答を含むため、記録をリポジトリに追加・共有しません。

シナリオは一意な試験名を使い、SimpleMQ キュー、実行設定、トリガー、`is1b` の通常スイッチを作成します。トリガーは `//eventbus.sakura.ad.jp/eventlog` の `jp.ad.sakura.eventbus.eventlog.IaaS.request.Switch.normal.created` を対象とし、イベントの `zone` が `is1b` のときだけ実行設定を起動します。SimpleMQ から一意な試験メッセージを受信したことを確認します。

同じシナリオ内でプロセス設定とトリガーの Update、update-secret、スケジュールのライフサイクルも検証します。プロセス設定の update はメッセージ内容を更新し、その内容を SimpleMQ 待ち受けが受信することでライブ更新を証明します。トリガーの update は説明のみを更新して復元します。スケジュールは現在時刻の1年後に1日周期で発火する設定を作成し、テスト時間内に発火しないため、一覧・参照・更新・削除を確認します。

事前確認で既に試験名が使われている場合は中止し、既存リソースを削除しません。後片付けでは取得した ID、名前、説明を再確認してからトリガー、実行設定、スイッチ、キューの順で削除し、一覧からの消失を確認します。作成 API がエラーを返しても作成済みの可能性がある場合は、名前と説明が完全一致するリソースだけを探して回収します。確認できない場合は削除せず、手動対応が必要なエラーを返します。

## 秘密情報と証跡

SimpleMQ の API キーは権限 `0600` の一時ファイルに保存します。EventBus のシークレット登録用 JSON も同じく `0600` で保存し、テスト終了時に両方を削除します。キーを CLI の引数へ渡さないため、`--api-key-file` と `--secret-file` の両方で同じ発行済みキーを使えます。API キー発行コマンドの stdout は実行記録に残さず、秘密情報が含まれるため省略したことを記録します。

E2E のシナリオ、既存リソース衝突時の中止、作成応答が不確定な場合の回収、ID 解釈と識別情報照合、API キー証跡の秘匿は `test/e2e/eventbus-api/` の単体テストで確認します。JSON 文字列と数値の両方のリソース ID の解釈、一覧が配列でない場合の拒否、プロセス設定・トリガー・スケジュールの設定照合、秘密情報ファイルのパーミッションと内容を検証します。

## 実機確認

2026-10-05 に選択中の SDK プロファイルでライブ E2E を実行し、`is1b` のスイッチ作成イベント後に設定したメッセージを SimpleMQ キューから受信できることを確認しました。後片付け後にスイッチ、トリガー、実行設定、キューが残っていないことも確認しました。この実行の証跡は新しい保存先形式へ移行しており、`ORDER.txt` で操作順を確認できます。

2026-10-27 に testing.T ベースのシナリオとして全工程を実行し、スイッチ作成イベント後に設定したメッセージを SimpleMQ キューから受信できることを確認しました。プロセス設定とトリガーの Update、update-secret、スケジュールのライフサイクルも同じ実行で検証しました。作成した ID と設定を削除直前に再照合して削除し、削除後の一覧に対象リソースがないことも確認しました。
