# IAM API コマンド

## 目的と範囲

`skr iam-api` は `sacloud-sdk-go v0.3.0` が公開する IAM API を操作します。実装と公開範囲の決定は [ADR 0031](../adr/0031-iam-api-commands.md) と [ADR 0032](../adr/0032-extend-iam-api-commands.md) に従います。

コマンドはユーザー、グループ、ポリシーバインディングに加え、認証条件、フォルダ、IAM ロール、ID ポリシー、ID ロール、組織、プロジェクト、プロジェクト API キー、SCIM、サービス利用ポリシー、サービスプリンシパル、SSO、ユーザー 2 要素認証を扱います。各 API 群が公開する操作、引数、JSON リクエスト、ヘルプは `api/commands/iam-*.json` に明記します。定型コマンドは `cmd/apigen-api` で生成し、CLI と SDK factory の接続は `internal/cli`、IAM の手書き処理とコマンド集約は `internal/iamapi` が担当します。

## 入力と秘密情報

単純な値は名前付きフラグまたは位置引数で指定し、配列や複雑なリクエストは `--request` に JSON または `@path.json` で指定します。`--request` と個別フラグは同時に指定できません。リスト操作は未指定時に SDK の既定条件で実行できるよう、生成設定の `request_optional` を使います。

サービスプリンシパルの update では、OpenAPI 定義の `required` 配列は `name` のみを含み、`description` は任意と定義されています。ogen 生成コードも定義に忠実に `Description` を `OptString` として扱います。しかし実際の API は `description` を必須として扱います。`description` を省いたリクエストに対して API は 400 を返し、`errors.description` に `code: required` を含めます。定義と実際の API の間に不整合があるため、CLI では実際の API 挙動に合わせて `--description` を必須にし、省略時の API エラーを事前に防ぎます。2026-10-26 にライブで確認しました。

ユーザーのパスワード、サービスプリンシパルの公開鍵とアサーションは専用のファイル入力を使い、値をコマンド引数に含めません。API キーや SCIM トークンなど、応答に秘密情報を含み得る操作は、保存先のアクセス制御と作成・再発行後の安全な取り扱いをヘルプおよび利用者向けチュートリアルで案内します。

## ライブ E2E

`test/e2e/iam-api` は testing.T ベースのシナリオテストです。`SKR_E2E` 環境変数が未設定のときはテストをスキップし、ライブ実行は `SAKURA_PROFILE=skr-e2e` のプロファイルを使います。シナリオはランダムな識別子を含むユーザー、グループ、フォルダ、プロジェクト、サービスプリンシパルを作成します。作成後に一覧・読み取り・更新を確認し、ユーザーのメールアドレスとグループ所属も一時的に登録して検証します。2026-10-29 に旧 runner ([ADR 0062](../adr/0062-e2e-testing-t-based-scenario.md)) から testing.T ベースのシナリオテストへ移行し、移行時に未検証だった `group update` のカバレッジを追加しました。group update は未指定項目を空で上書きするため、名前と説明を毎回指定して更新し、応答と元の名前に戻した後の読み込みで反映を確認します。

E2E は既存名との衝突を事前確認し、リソースの ID、名前、説明、必要に応じてコードとプロジェクト ID を照合します。削除前にも作成時の識別条件を再確認し、サービスプリンシパル、グループ、ユーザー、プロジェクト、フォルダの順に削除します。失敗時にも作成が試みられたリソースを検索して回収します。ページングでは API の次ページ情報、または次ページ情報がない一覧の元データ件数を確認します。対象名の投影結果が空であることだけでは終了せず、最終ページまで走査します。

組織全体の設定に影響する更新は、読み取った値をそのまま送り返す同一値の往復で実行し、組織設定を変更しません。対象は認証条件、パスワードポリシー、ID ポリシー、組織ポリシー、組織名、サービス利用設定のルールです。サービス利用設定は無効状態での update が 409 で拒否されるため、有効化してから同一ルールで更新し、無効化に戻します。SCIM と SSO は組織全体の設定ですが、シナリオが作成した設定の作成・読み取り・一覧・更新・削除を同じシナリオ内で確認します。SSO の link/unlink は既存ユーザーのログイン方法に影響するため実行せず、[#144](https://github.com/sacloud/skr/issues/144) で対応します。2 要素認証は使い捨ての一時ユーザーに対して、空ページの参照と `deactivate-otp`・`clear-trusted-devices` の正常終了、存在しない ID の操作が 404 で分類されることを確認します。API キーはシナリオが作成したプロジェクト内でライフサイクルを確認し、応答に access token が含まれる create と read は `--query` で投影して実行記録にトークンを残しません。サービスプリンシパルのキーも同じで、公開鍵と JWT アサーションは専用のファイル入力で渡します。実行方法と注意事項は [IAM API チュートリアル](../manual/tutorials/iam-api.md) を参照してください。
