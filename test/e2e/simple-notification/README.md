# simple-notification E2E

Simple Notification API コマンドのライブ E2E です。設計の詳細は [Simple Notification API コマンド設計](../../docs/design/simple-notification-api.md) を参照してください。

## シナリオ

このディレクトリには、目的と使うリソースが異なる2つのシナリオがあります。

| テスト | 実行記録の識別名 | 内容 |
| --- | --- | --- |
| `TestScenarioSimpleNotification` | `simple-notification-send` | 既存の確認済み通知先へテスト通知を送信し、一時グループの作成・参照・一覧、通知履歴の照合、履歴の個別参照、削除と不在確認まで行います |
| `TestScenarioSimpleNotificationCRUDOnly` | `simple-notification-crud-only` | 通知を送信せずに、一時通知先・グループ・ルーティングの作成・参照・一覧・更新・削除と、一時ルーティングの並べ替えを確認します |

## シナリオが2系統ある理由

新規に作成した通知先は、確認メールへの応答が完了するまで無効です。このため、実際に通知を送る検証と通知先の設定を自由に変更する検証とでは、必要なリソースの状態が正反対になり、1つのシナリオでは両方を満たせません。

- 通知送信シナリオは、メール確認の完了した通知先が必要です。確認済みなのは既存通知先だけです。既存通知先は利用者が承認した実リソースのため、変更・削除しません。シナリオは既存通知先を読み取り専用で一時グループに入れ、通知を送信します。
- CRUD シナリオは、通知先の有効・無効の切り替えやメタデータ更新を試すため、設定を自由に変更できる通知先が必要です。既存通知先は変更できないため、既存通知先と同じアドレスの一時通知先を作成します。作成した一時通知先は未確認のため送信に使えず、`send-message` は呼び出しません。ルーティングも通知元とターゲットグループが必要なため、このシナリオだけで検証します。

## 実行前の確認

- `SKR_E2E` が設定されていない場合、テストはスキップされます。
- 認証は `skr-e2e` プロファイルを使います。プロファイルが存在しない場合もテストはスキップされます。
- `SKR_E2E_SIMPLE_NOTIFICATION_DESTINATION_ID` に、利用者が承認した既存のメール確認済み通知先の ID を指定します。未設定の場合はテストをスキップします。
- 通知送信シナリオを実行すると、指定した既存通知先に実際にテスト通知が送信されます。
- CRUD シナリオでは、一時通知先の登録時に確認メールが送信されます。

## 実行方法

```console
$ SKR_E2E=1 SKR_E2E_SIMPLE_NOTIFICATION_DESTINATION_ID=DESTINATION-ID go test ./test/e2e/simple-notification/
```

`-run` で実行するシナリオを絞り込めます。実行記録は Git 対象外の `e2e-output/` 配下に `<識別名>-<実行日時>.md` で保存されます。
